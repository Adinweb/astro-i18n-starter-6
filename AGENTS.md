> **Target Audience:** AI Coding Agents (Claude Code, Cursor, Copilot, Codex, Gemini, Windsurf).  
> **Repository:** Production-Grade Astro v7 SSG Multilingual Starter with Native RTL/LTR Support.  
> **Version:** 5.0

## 1. Prime Directive & Contract Rules

When working in this repository, you **MUST** follow these non-negotiable rules:

1. **One Source of Truth (SSOT)**:
   - Locales & directions: `src/i18n/locales.ts` and `project.inlang/settings.json`.
   - Locale-native numbers & dates: `src/i18n/format.ts` (`formatNumber`, `formatDate`).
   - Paths & URLs: `src/i18n/paths.ts` (`localizeHref`, `localeHref`, `stripLocale`).
   - Content schemas: `src/content.config.ts`.
   - Slugs, feeds & alternates: `src/libs/content/service.ts` and `src/libs/content/feed.ts`.
   - Content entry invariants (IDs, drafts, locale selection, sorting): `src/libs/content/entries.ts`.
   - Blog filters & reading time: `src/libs/content/blog.ts`; taxonomy labels: `src/libs/content/taxonomy.ts`.
   - Application config: `app.config.json`, validated and typed by `src/libs/config/app.ts` (`siteConfig`, `POSTS_PER_PAGE`, brand assets, dev server).
   - Blog pagination: page size `blog.postsPerPage` in `app.config.json` (exposed as `POSTS_PER_PAGE`), page math in `src/libs/content/pagination.ts` (`paginate`, `buildPageWindow`), page URLs in `src/libs/content/service.ts` (`getBlogPageHref`).
   - UI copy: Compiled Paraglide messages (`import * as m from '@/paraglide/messages'`). Never hardcode UI text.
2. **Lean Router Dispatcher Pattern**:
   - Never create dynamic routing files (`[lang].astro`, `[slug].astro`) under `src/pages/`.
   - All dynamic routing flows exclusively through `src/pages/[...path].astro`, which dispatches to views in `src/views/`. This completely eliminates Astro route collisions.
3. **Prefix-less Default Locale**:
   - The default locale (`DEFAULT_LOCALE = 'en'`) has **no prefix** (`/`, `/about`, `/blog/first-post`).
   - Non-default locales (`de`, `fr`, `fa`, `ar`) have prefixes (`/de/about`, `/fa/درباره-ما`, `/ar/من-نحن`).
   - Never write hardcoded `/en/` or `/fa/` paths in templates or logic.
4. **RTL-Native Discipline**:
   - Always use CSS logical properties (`ms-`, `me-`, `ps-`, `pe-`, `start-*`, `end-*`, `text-start`, `text-end`, `border-s-*`, `border-e-*`).
   - Never use physical directions (`ml-`, `mr-`, `pl-`, `pr-`, `left-`, `right-`, `text-left`, `text-right`).
   - Code blocks (`pre`, `code`, `.math`) are strictly isolated to `ltr` via `src/styles/prose.css`.
5. **Untouchable Generated Code**:
   - `src/paraglide/` is auto-generated by `@inlang/paraglide-js`. **Never hand-edit files in `src/paraglide/`**. Always edit `messages/<locale>.json` and run `pnpm run messages:compile`.
6. **Static Language Switching**:
   - Language switching requires full static browser navigation (`window.location.assign(target)`) rather than client-side SPA view transitions, guaranteeing that `<html lang="..." dir="...">`, typography stacks, and CSS `:lang()` pseudo-classes are fully applied.
7. **Idempotent Client Scripts**:
   - In Astro components using `<ClientRouter />`, `astro:page-load` fires on both initial load and every client transition. Always guard DOM element listeners with `if (el.dataset.bound === 'true') return; el.dataset.bound = 'true';`.
8. **Render-Time Message Invocation**:
   - Call `m.<key>({}, { locale })` inside component render cycles or templates. Never call message functions at module evaluation scope.
9. **Shared Visual Language**:
   - Frosted surfaces, buttons and chips are defined **once** in `src/styles/global.css` (`.glass-surface`, `.glass-control`, `.ghost-control`, `.cta`, `.btn-secondary`, `.chip`). Never re-declare those treatments in a component; compose the class instead.
   - Icon-only controls are rendered by `src/components/IconButton.astro`. Do not hand-roll a `<button>` with an `<Icon>` inside.
   - Shared hero copy (heading, description, slots) lives in `src/components/HeroCopy.astro`. Pages, the blog index and blog posts all compose it, so the typography cannot drift.

## 3. Essential Commands & Verification Suite

Always use these exact pnpm scripts:

| Command | Purpose | When to Run |
| :--- | :--- | :--- |
| `pnpm run messages:compile` | Compiles `messages/*.json` into `src/paraglide/` | After modifying dictionary keys |
| `pnpm run lint` | Messages compile + `astro check` + `tsc --noEmit` | After any code changes |
| `pnpm test` | Vitest unit tests (paths, ICU plurals/ordinals, routes, CLI helpers) | After routing or logic changes |
| `pnpm run audit:i18n` | Locale-config parity, dictionary/placeholder parity, content parity, used keys, slug & route collisions | Before commits & builds |
| `pnpm run verify:cli` | End-to-end check of every documented CLI workflow (45 claims, runs in a temp copy) | After changing anything under `scripts/` |
| `pnpm run build` | `messages:compile` + audit + `astro build` + `pagefind` | After major changes |
| `pnpm run smoke` | HTML, SEO, feed, asset & H1 assertions on `dist/` | After every production build |
| `pnpm run knip` | Dead files, exports, and dependencies | Before releases |
| `pnpm run assets:generate` | Regenerate PNG icons, the OG image and all hero/cover artwork | After brand changes or when a page/post group is added |

### Dev Server Management
In this environment, start the server using background mode:
```bash
astro dev --background
```
Manage the server using `astro dev status`, `astro dev logs`, and `astro dev stop`.

After `pnpm install` (or any change to `node_modules`), **restart the dev server**: a
server that was started before the install keeps its stale module graph and fails
with `Unknown file extension ".astro"`.

## 4. Built-in CLI Automation Suite (`scripts/`)

Agents should execute these scripts instead of performing brittle manual file manipulations:

### 4.1 Content Scaffolding
* **Create or update a static page group across all locales:**
  ```bash
  pnpm run new:page <page-key> [--title="<Title>"] [--from=<source-locale>] [--image=cover.png|none] [--publish]
  # Update existing page frontmatter across all locales without overwriting markdown bodies:
  pnpm run new:page <page-key> --update [--sync-frontmatter] [--title="<New Title>"] [--desc="<New Desc>"]
  ```
  *Example:* `pnpm run new:page contact --title="Contact Us" --from=en`  
  *Actions performed:* Creates or updates `src/content/pages/contact/{en,de,fr,fa,ar}.mdx`, generates localized slugs, preserves body copy, registers the `nav_contact` key across all dictionaries, and points every locale's `image` frontmatter at the page's hero background. Without `--image`, the page uses the generated `./<page-key>.png` (next to the entries) and `assets:generate` is run to create it. With `--image`, the file is looked up next to the content group and in the project root, then copied into the group folder, because the frontmatter reference is relative to the entry file. A named image that does not exist is a **warning**, not a failure: the group artwork is used instead.  
  *Publication:* Without a draft flag only the **source locale** is published (`draft: false`); every other locale stays `draft: true` until it is translated. `--publish` / `--draft=false` publishes the source and every locale that has a real `--title:<locale>` / `--desc:<locale>`; locales that still contain `[TODO: ...]` placeholders stay drafts. `--draft` / `--draft=true` drafts all of them.  
  *Slugs:* The source and default locale use the group key (`contact`); the other locales get a placeholder (`contact-fa`) until a native slug is set with `--slug:<locale>="…"`.

* **Create or update a blog article across all locales:**
  ```bash
  pnpm run new:post <group-slug> [--from=<source-locale>] [--title="<Title>"] [--publish]
  # Update existing post frontmatter across all locales without manual file rewrites:
  pnpm run new:post <group-slug> --update [--sync-frontmatter] [--title="<New Title>"] [--desc="<New Desc>"]
  ```
  *Example:* `pnpm run new:post ai-agents --from=en --title="AI Coding Agents" --category=engineering --tags="astro,i18n" --image=cover.png --publish`  
  *Actions performed:* Creates or updates `src/content/blog/ai-agents/{en,de,fr,fa,ar}.mdx` with synchronized frontmatter, including `categories`, `tags`, and the featured `image` (the group cover `./<group>.png` by default, or the shared artwork with `--image=none`).  
  *Note:* `--from` selects the **source locale**, it does not copy the body of another article; use `--clone-from=<group>` for that. Publication and slug rules are identical to `new:page`.

### 4.2 Content Removal
* **Remove an entire page or a single locale:**
  ```bash
  pnpm run remove:page <page-key> [--locale=<locale>] [--force]
  ```
  *Actions performed:* Deletes content folder, cleans `nav_<key>` from dictionaries, and recompiles Paraglide. With `--locale`, only that locale's file is deleted and the `nav_<key>` key **stays** in every dictionary: the dictionaries always carry the same key set, and a missing locale is reported by the audit as a warning, not an error.
* **Remove a blog article:**
  ```bash
  pnpm run remove:post <group-slug> [--locale=<locale>] [--force]
  ```

### 4.3 Language Management
* **Add a new language to the site:**
  ```bash
  pnpm run i18n:add-lang -- <locale-code> [--name="<Name>"] [--dir="ltr|rtl"] --with-content --from=en
  ```
  *Example:* `pnpm run i18n:add-lang -- es --name="Español" --dir="ltr" --with-content --from=en`  
  *Actions performed:* Updates `project.inlang/settings.json`, creates `messages/<locale>.json`, updates `src/i18n/locales.ts`, generates `<locale>.mdx` files across all existing pages and posts, and recompiles Paraglide. Generated entries stay `draft: true`, because their copy is still placeholder text. `--publish` cannot override a `[TODO: ...]` title: translate the entry and flip its `draft` flag when it is ready.

* **Remove a language:**
  ```bash
  pnpm run i18n:remove-lang -- <locale-code> --with-content --force
  ```

### 4.4 Translation & Styling Automation
* **Adapt raw external Tailwind blocks to RTL & semantic tokens:**
  ```bash
  pnpm run block:adapt -- --file=<path-to-component-or-view>
  ```
  *Actions performed:* Parses attributes with `magic-string`; converts `ml-` → `ms-`, `mr-` → `me-`, `pl-` → `ps-`, `pr-` → `pe-`, `left-` → `start-`, `right-` → `end-`, `bg-white` → `bg-bg`, `text-gray-900` → `text-fg`, `border-gray-200` → `border-border`.

* **Extract hardcoded strings from component markup:**
  ```bash
  pnpm run i18n:extract -- --target=<file-or-dir> --key=<namespace> --auto-add --replace
  ```

* **Add a single translation key:**
  ```bash
  pnpm run i18n:add -- --category=<cat> --key=<key> --en="English" --fa="فارسی" --ar="العربية" --de="Deutsch" --fr="Français"
  ```

* **Batch add translation keys (JSON file, CLI JSON, or stdin):**
  ```bash
  pnpm run i18n:add-batch -- --file=translations.json [--category=<cat>]
  pnpm run i18n:add-batch -- --json='{"cart_checkout": {"en": "Checkout", "fa": "تسویه حساب"}}'
  cat keys.json | pnpm run i18n:add-batch
  ```
  *Actions performed:* Merges multiple keys into all locale dictionaries with automatic parity placeholders, sorts keys alphabetically, and triggers a single Paraglide recompile.

## 5. Playbooks for Common Agent Tasks

### Playbook A: Adding a New Navigation Link
1. Verify the static page exists under `src/content/pages/<page-key>/`. If not, run `pnpm run new:page <page-key>` (this also registers `nav_<page-key>`).
2. Add the page group to `PAGE_ITEMS` in `src/libs/config/navigation.ts`:
   ```ts
   { group: '<page-key>', label: (locale) => m.nav_<page-key>({}, { locale }) }
   ```
3. The desktop header, mobile dialog, and footer all consume `getNavigation()`, so no template edits are needed. Missing locale files are skipped automatically.
4. Run `pnpm run lint && pnpm test && pnpm run audit:i18n`.

### Playbook B: Swapping the Default Locale
To make another language (e.g., Farsi `fa` or Arabic `ar`) the prefix-less default:
1. Open `src/i18n/locales.ts` and change `DEFAULT_LOCALE`:
   ```typescript
   export const DEFAULT_LOCALE: Locale = 'fa';
   ```
2. Open `project.inlang/settings.json` and change `baseLocale`:
   ```json
   "baseLocale": "fa"
   ```
3. Run:
   ```bash
   pnpm run messages:compile && pnpm test && pnpm run audit:i18n && pnpm run build && pnpm run smoke
   ```
   *Result:* Persian instantly routes to `/`, `/darbare-ma`, `/blog/اولین-پست`, while English routes to `/en/`, `/en/about/`, etc.

### Playbook C: The Hero Background
The hero band is rendered by `src/components/PageHero.astro`. The page's or post's image **is** the background of the section — one full-bleed image layer, never a card beside the copy and never a duplicated layer.

1. The background comes from the entry's `image` frontmatter — a path **relative to the content file** (`./<group>.png`). Without one, `DEFAULT_HERO_IMAGE` (`src/assets/hero/hero-0.jpg`) is used.
2. The path is resolved by Astro's `image()` schema helper in `src/content.config.ts`: it resolves the reference against the entry file, checks that the file exists and hands the entry ready-made image metadata. A missing file therefore fails the build instead of shipping a broken hero. The artwork of a group lives next to its entries (`src/content/<collection>/<group>/<group>.png`), because that is where the relative reference points.
3. Inner content is supplied through the default slot: `HeroCopy.astro` for pages and the blog index, `BlogPostHeroContent.astro` for posts (which composes `HeroCopy`). `PageHero` itself renders no copy.
4. The image is **defocused** (`blur-md` plus a `scale-105` so the soft edge stays hidden) — it reads as atmosphere, not as a competing picture. The copy sits on top of it.
5. Three overlays shape the light: a flat tonal wash (`bg-fg/35`), a bottom scrim and a wash under the fixed header. All of them are vertical or flat, so the band is identical in LTR and RTL. Keep it that way: a horizontal scrim would need an `rtl:` variant.
6. The per-group artwork is drawn from code by `scripts/generate-assets.mjs`. Run `pnpm run assets:generate` after adding a page or post group, or after changing the palette in that script. The palette is luminance-normalised, so every hue reads at the same perceived brightness. The shared hero photograph is **not** generated — it is a real image in `src/assets/hero/`.
7. The picture is rendered with `<Image>`: WebP output, a `srcset` of responsive widths and `sizes="100vw"`. The widths are capped at the width of the source so the picture is never upscaled.
8. The image element carries `transition:persist` keyed by its path, so the same artwork is never decoded twice during client-side navigation, and a different artwork always replaces it.

### Playbook D: Adding an SVG Icon
1. Open `src/pages/icons.svg.ts`.
2. Add the SVG `<path>` inner content to the `icons` object:
   ```typescript
   const icons: Record<string, string> = {
     // ...
     star: '<path d="M12 2l3.09 6.26L22 9.27l-5 4.87 1.18 6.88L12 17.77l-6.18 3.25L7 14.14 2 9.27l6.91-1.01L12 2z" stroke="currentColor" stroke-width="2" fill="none"/>',
   };
   ```
3. In components, use:
   ```astro
   <Icon name="star" size={20} class="text-primary" />
   ```
   *Never paste raw `<svg>` with inline paths directly into templates.*

### Playbook E: Changing the Blog Pagination
The blog index is a static, paginated listing. One page of posts is one route, and the route set is derived from the content — never hand-written.

1. The page size is `blog.postsPerPage` in `app.config.json`:
   ```json
   "blog": { "postsPerPage": 9 }
   ```
   `src/libs/config/app.ts` exposes it as `POSTS_PER_PAGE`. Both the route builder (`src/libs/content/service.ts`) and the view (`src/views/BlogIndexView.astro`) read that value, and the smoke test counts from it, so generated pages and rendered cards can never drift apart.
2. The URL of a page is built by `getBlogPageHref(page, locale)`:
   * page 1 → `/blog/` (the index itself, prefix-less in the default locale)
   * page 2+ → `/blog/page/2/` (localized: `/de/blog/page/2/`, `/fa/blog/page/2/`)
   *Never* hardcode `/blog/page/2` — the locale prefix and the trailing slash are the job of `localizeHref`.
3. The page math is pure and lives in `src/libs/content/pagination.ts`:
   * `paginate(items, page, perPage)` slices the list and reports `previousPage` / `nextPage`.
   * `buildPageWindow(page, totalPages)` renders the number window; holes become the `PAGE_GAP` ellipsis.
   * A requested page is always clamped into `1..totalPages`, so a stale link (`/blog/page/99/`) can never produce an out-of-range slice.
4. `buildSiteRoutes()` registers one `blog-index` route per page **per locale**, and the page count of a locale follows from the number of *published* posts that locale has. A locale with fewer posts falls back to its last page in the `alternates` map, so the language switcher never leads to a missing URL.
5. The pager is rendered by `src/views/BlogIndexView.astro`:
   * it is only rendered when there is more than one page;
   * the previous/next arrows use the `chevron-left` icon flipped with `rtl:rotate-180` / `rotate-180 rtl:rotate-0`, so the direction follows the reading direction;
   * every pager link carries the active taxonomy filter query, so paging never drops the selection.
6. `Seo.astro` / `BaseLayout.astro` accept `prevUrl` / `nextUrl` and emit `<link rel="prev">` / `<link rel="next">` for the paginated pages. The document title of page two and beyond is `Blog — Page 2 of 3`.
7. After a change run:
   ```bash
   pnpm run lint && pnpm test && pnpm run audit:i18n && pnpm run build && pnpm run smoke
   ```
   `pnpm run smoke` derives the expected page count from the content collection and asserts that every page exists, that `rel="prev"` / `rel="next"` point at the right neighbours, and that no page beyond the last one was generated.

## 6. Forbidden Anti-Patterns (Zero Tolerance)

| ❌ Forbidden Pattern | ✅ Correct Pattern |
| :--- | :--- |
| Hardcoding paths like `/en/about` or `/fa/blog` | Use `localizeHref('/about', locale)` or `getPageUrl('about', locale)` |
| Using physical directions (`ml-4`, `pr-6`, `text-left`) | Use logical properties (`ms-4`, `pe-6`, `text-start`) |
| Hand-editing files in `src/paraglide/` | Edit `messages/<lang>.json` and run `pnpm run messages:compile` |
| Calling `m.key()` at top-level module scope | Call `m.key({}, { locale })` inside template/render cycle |
| Creating `src/pages/[lang]/...` route files | Use `src/pages/[...path].astro` dispatcher with `src/views/` |
| Inline `<svg>` `<path>` blobs in HTML | Add icon symbol to `src/pages/icons.svg.ts` and use `<Icon name="..." />` |
| Using `navigate()` for language switching | Use `window.location.assign(target)` for static language switch |
| Missing `el.dataset.bound` guard in scripts | Check `if (el.dataset.bound === 'true') return; el.dataset.bound = 'true';` |
| Showing the hero image as a card next to the copy, or duplicating it | Make the image the section background (one full-bleed layer) in `PageHero.astro` |
| Shipping a dark hero illustration under a heavy scrim | Keep the artwork luminous (`assets:generate`) and the scrim light |
| Re-declaring a button, chip or frosted surface in a component | Compose `.cta`, `.btn-secondary`, `.chip`, `.glass-*` from `src/styles/global.css` |
| Hand-rolling an icon-only `<button>` with an `<Icon>` inside | Use `<IconButton icon="..." label="..." />` |
| Serving a page image from `public/` or with a raw `<img src>` | Keep it next to the content entry, reference it as `./<file>.png` and render it with `<Image />` |
| Rendering every blog post on one page, or hardcoding `/blog/page/2` | Slice with `paginate()` and link with `getBlogPageHref(page, locale)` |
