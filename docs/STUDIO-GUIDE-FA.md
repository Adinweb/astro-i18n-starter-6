# راهنمای جامع کار با Studio در Astro i18n Starter

> **استودیو (Dev Studio)** یک پنل مدیریت بصری و محلی (فقط در محیط توسعه) است که بدون نیاز به دست‌کاری کد یا اجرای تک‌تک اسکریپت‌های CLI، تمام بخش‌های پروژهٔ **Astro v7** (راه‌اندازی سایت مشتری، پیکربندی سه‌لایه، منوهای درختی، اسکیمای محتوا، صفحات MDX، ماتریس ترجمه و تست‌های بیلد) را مدیریت می‌کند.
> این فایل تمام قابلیت‌های Studio و معادل مستقیم آن‌ها در فایل‌های JSON / CLI را پوشش می‌دهد.

## ۱. نحوهٔ اجرا و دسترسی

Studio به دو روش قابل دسترسی است و هر دو روش دقیقاً به یک رابط کاربری و API متصل هستند:

1. **در حین اجرای سرور توسعه (`npm run dev`):**
   کافی است آدرس `/__studio/` را در مرورگر باز کنید (مثلاً `http://localhost:3000/__studio/`).
2. **به‌صورت سرور مستقل بدون اجرای کامل سایت:**
   ```bash
   npm run studio
   ```
   به‌صورت پیش‌فرض روی `http://127.0.0.1:4322/` بالا می‌آید. در صورت نیاز می‌توانید پورت، هاست یا لینک پیش‌نمایش سایت را تغییر دهید:
   ```bash
   npm run studio -- --port=4322 --host=127.0.0.1 --preview-url=http://localhost:3000
   ```

## ۲. آشنایی با نوار بالا و ابزارهای سراسری

در هدر بالایی Studio ابزارهای زیر همیشه در دسترس‌اند:

- **نشانگرهای وضعیت (Badges):** نام بسته، نام سایت، زبان پیش‌فرض و زبان‌های فعال، تعداد کلیدهای ترجمهٔ جاافتاده، هشدار همگام نبودن `.pages.yml` و **نشانگر سلامت پروژه (Health)**. با کلیک روی نشانگر سلامت، گزارش کامل خطاها و هشدارها همراه با دکمهٔ پرش مستقیم به بخش مربوطه باز می‌شود.
- **مدیر رسانه (`🖼 رسانه`):** مشاهدهٔ تمام تصاویر موجود در `public/` و `src/assets/`، جستجو، کپی مسیر و آپلود مستقیم تصویر جدید (`SVG`, `PNG`, `WebP`, `AVIF`, `JPG`) به پوشهٔ `src/assets/uploads/`.
- **پیش‌نمایش زندهٔ دوتایی (`◫ پیش‌نمایش زنده`):** در حالت اجرای Studio روی `/__studio/` یا با تنظیم `--preview-url`، پنجرهٔ سایت را به‌صورت Split-Screen کنار پنل ویرایش باز می‌کند؛ همراه با سوییچ نمای **Desktop / Tablet (`768px`) / Mobile (`390px`)**، نوار آدرس و رفرش خودکار پس از ذخیرهٔ تغییرات.
- **محافظ تغییرات ذخیره‌نشده (Dirty Guard):** نمایش نقطهٔ هشدار روی تب‌های دارای ویرایش ذخیره‌نشده، دکمه‌های **«لغو تغییرات»** (`Discard`) و جلوگیری از بسته شدن تصادفی تب مرورگر.
- **تازه‌سازی (`↻ Refresh`)، زبان پنل (`EN / فا`) و تم (`☀ / ☾`):** رابط کاربری خود Studio کاملاً دوزبانه (فارسی RTL / انگلیسی LTR) و دارای تم روشن/تیره است.
- **داک کنسول پایین صفحه (`خروجی دستورات و لاگ`):** خروجی تمام دستورات CLI و عملیات ساخت/تست را با زمان اجرا نمایش می‌دهد.

## ۳. تب ۱: هویت پروژه و راه‌انداز

این تب برای شروع یک پروژهٔ جدید مشتری طراحی شده و شامل دو کارت اصلی است:

### الف) هویت پروژه، ریپازیتوری و متغیرهای `.env`
- ویرایش **`package.json`**: نام پکیج (`name`)، نسخه (`version`)، لایسنس، نویسنده و توضیحات.
- ویرایش **`metadata.json`**: نام و توضیحات اپلیکیشن.
- ویرایش کلیدهای مجاز **`.env`**: مقادیری مانند `SITE_URL`، `PUBLIC_API_BASE_URL`، `PUBLIC_CONTACT_API_URL`، `PUBLIC_NEWSLETTER_API_URL`، `PUBLIC_TURNSTILE_SITE_KEY` و `PUBLIC_WEB3FORMS_KEY`.
- با دکمهٔ **«ذخیره هویت پروژه و .env»** این سه فایل به‌روزرسانی می‌شوند.

### ب) راه‌انداز سریع سایت مشتری (`site:apply`)
در این بخش می‌توانید کل ساختار اولیهٔ سایت را در یک مرحله بسازید:
1. **بلوپرینت دامنه (`blueprint`):** انتخاب یکی از الگوهای آماده (شرکتی، آژانس، پورتفولیو، پزشکی، کاتالوگ، حقوقی) تا کالکشن‌های تخصصی مرتبط ساخته شوند.
2. **اطلاعات پایه سایت:** نام، نام کوتاه، ایمیل تماس، نویسنده، توضیحات، زبان پیش‌فرض و حالت تک‌زبانه (`solo`).
3. **برندینگ و لوگو:** پالت رنگی، رنگ‌های سفارشی، فونت لاتین و فونت فارسی/RTL، حالت کارت‌های سوشال و آپلود لوگوی روشن/تیره.
4. **صفحات استارتر:** انتخاب صفحاتی مثل `about`، `features`، `pricing`، `contact`، `privacy` و `terms` برای ایجاد و انتشار خودکار.
5. **ترکیب‌بندی صفحه اصلی (`ui.homeSections`):** افزودن، مرتب‌سازی و ویرایش سریع سکشن‌ها و هیروهای صفحه اول.
6. **اجرا:** می‌توانید با **«کپی JSON»** خروجی `spec` را بردارید، با **«پیش‌نمایش Dry-Run»** تغییرات را بدون نوشتن روی دیسک بررسی کنید، یا با **«اعمال و ساخت سایت»** همه را یک‌جا اعمال کنید.

## ۴. تب ۲: تنظیمات و برندینگ

این تب مستقیماً فایل **`client/config.json`** را مدیریت می‌کند (پیکربندی سه‌لایه به ترتیب اولویت: `app.config.json` ← `client/config.json` ← `client/cms.json`). Studio فقط تفاوت‌های نسبت به `app.config.json` را به‌صورت **Sparse JSON** در `client/config.json` ذخیره می‌کند.

زیرتب‌های این بخش:
1. **هویت سایت و نویسندگان (`site`):** مشخصات عمومی سایت و مدیریت پروفایل نویسندگان (`site.authors`) برای وبلاگ و Schema.org.
2. **برند، رنگ، فونت و لوگو (`brand`):** انتخاب پالت (`preset`)، تم پیش‌فرض (`system/light/dark`)، فونت، و آپلود/تنظیم لوگوی روشن و تیره (`brand.logo`).
3. **رابط کاربری، نوبار و موشن (`ui`):** دکمهٔ CTA هدر (`ui.ctaPage`)، نمایش جستجو/سوییچر زبان/تغییر تم، تنظیمات چسبندگی نوبار (`ui.navbar`)، پارامترهای انیمیشن ChronoTrig/Lenis (`ui.motion`) و مدیریت سکشن‌های صفحه اصلی (`ui.homeSections`).
4. **بنر اطلاع‌رسانی و تماس سریع (`banner`):** مدیریت `ui.topBanner` (زمان‌بندی، بنرهای چندگانه، متن به تفکیک زبان، مسیرهای مستثنا) و ویجت شناور `ui.quickContact` (تلفن، واتساپ، تلگرام).
5. **کسب‌وکار، سوشال و وبلاگ (`business`):** نوع Schema.org (`Organization`, `LocalBusiness`, ...)، آدرس و مختصات نقشه، شبکه‌های اجتماعی و تنظیمات وبلاگ (`postsPerPage`, TOC و...).
6. **آنالیتیکس، کوکی و API فرم‌ها (`analytics`):** شناسهٔ GA4 / GTM / Clarity / Plausible / Umami، تنظیمات بنر کوکی (`cookies`) و انتخاب ارائه‌دهندهٔ فرم‌ها (`custom`, `web3forms`, `formspree`, `basin`, `webhook` + کلید Turnstile و `api.topics`).
7. **منوها، ناوبری و سرور (`nav`):** مدیریت منوهای درختی با آیدی یکتا، اتصال به جایگاه‌ها، ریدایرکت‌ها (`redirects`) و تنظیمات هاست/پورت سرور.

> **نکته:** در پایین این تب دکمه‌های **«نمایش/مخفی کردن Diff فعلی»**، **«خروجی / ورودی پکیج کلاینت»** (انتقال یک‌جای تنظیمات کلاینت بین پروژه‌ها)، **«بازنشانی `client/config.json`»** (`site:reset`)، **«لغو تغییرات»** (`Discard`) و **«ذخیره تغییرات در `client/config.json`»** قرار دارند. همچنین در سکشن‌ها (`ui.homeSections` و سکشن صفحات) علاوه بر فیلدهای متنی و `surface`/`spacing`، فیلدهای `columns`، انتخابگر تصویر از مدیر رسانه (`🖼`) و دکمه‌های `primaryCta`/`secondaryCta` نیز به‌صورت فرم و همگام با JSON در دسترس هستند.

## ۵. آموزش کامل مدیریت منوهای درختی و جایگاه‌ها

در زیرتب **«منوها، ناوبری و سرور»** می‌توانید منوهای چندسطحی بسازید و هر منو را هم‌زمان در چند جایگاه با حالت نمایش متفاوت استفاده کنید.

### الف) ساخت منو
- روی **`+ منوی جدید`** کلیک کنید (یا از **`+ ایجاد منوی نمونه از صفحات فعلی`** برای ساخت خودکار منو از صفحات فعلی کمک بگیرید).
- برای منو یک **`id` یکتا** (با حروف انگلیسی، عدد، `_` یا `-`؛ مثلاً `main-nav` یا `services-menu`) و یک عنوان (`title` و `titles` چندزبانه) وارد کنید.
- **حالت پیش‌فرض زیرمنو (`displayMode`):**
  - `dropdown` (کشویی): زیرلینک‌ها به‌صورت زیرمنوی بازشونده نمایش داده می‌شوند.
  - `list` (لیست باز): زیرلینک‌ها به‌صورت درخت توکار و همیشه باز رندر می‌شوند.

### ب) افزودن و ویرایش آیتم‌ها به شکل درختی
- **`+ افزودن لینک ریشه`:** ساخت آیتم در سطح اول منو.
- **`+ زیرلینک` (روی هر کارت آیتم):** افزودن فرزند به زیرمجموعهٔ همان آیتم (با عمق نامحدود).
- **ابزارهای جابه‌جایی و ساختار:**
  - `↑` / `↓`: تغییر ترتیب در همان سطح.
  - `↳`: تبدیل آیتم به زیرمجموعهٔ آیتم قبلی (افزایش عمق).
  - `↰`: بیرون آوردن آیتم یک سطح به بالا (کاهش عمق).
  - `✕`: حذف آیتم و زیرمجموعه‌هایش.
- **نوع لینک (`Link Target`):**
  1. `صفحه سایت (group)`: اتصال امن به گروه صفحه (مثل `about`، `pricing`)؛ اگر صفحه منتشر نشده یا در زبان مقصد وجود نداشته باشد، لینک به‌شکل ایمن مدیریت می‌شود.
  2. `بخش محتوا (contentType)`: لینک به صفحهٔ شاخص یک کالکشن (مثل `blog` یا `projects`).
  3. `لینک دلخواه / انکر (href)`: مسیر نسبی، انکر (مثل `/features/#rtl`) یا لینک خارجی (با تیک `ext` برای `external: true`).
  4. `گروه والد بدون لینک (Branch)`: سرگروه بدون لینک که فقط میزبان زیرمنوهاست (برایش `id` تعریف کنید).
- **برچسب و آیکون:** برچسب پیش‌فرض (`label`)، برچسب‌های چندزبانه (`labels.fa`، `labels.en` و...) و انتخابگر بصری آیکون (`🎨`) با جستجو در تمام آیکون‌های ثبت‌شدهٔ Tabler.
- **باز و بسته کردن شاخه‌ها و انتقال JSON:** دکمه‌های `▾`/`▸` روی گره‌های شاخه‌ای، دکمه‌های **«باز کردن همه / بستن همه»** برای مدیریت راحت منوهای بزرگ، و دکمهٔ **`{ } JSON`** در نوار منو برای کپی، دانلود یا ایمپورت مستقیم JSON یک منو.
- **نمایش زیرلینک‌ها روی خود گره (`childrenDisplay`):** به‌صورت پیش‌فرض روی `ارث‌بری از منو (inherit)` است، اما می‌توانید فقط برای یک شاخهٔ خاص آن را به `dropdown` یا `list` تغییر دهید.
- پایین کادر ویرایشگر، **«پیش‌نمایش ساختار درختی منو»** لحظه‌به‌لحظه ساختار نهایی درخت را به شما نشان می‌دهد.

### ج) تعیین جایگاه نمایش و انتخاب Dropdown یا List در زمان جای‌گذاری
یک منو را می‌توانید هم‌زمان در چند نقطهٔ سایت قرار دهید و در هر نقطه مستقل تصمیم بگیرید چطور رندر شود:

1. **در بخش `ui.navigation.slots` داخل همین زیرتب:**
   - **هدر دسکتاپ (`slots.header` + `headerDisplayMode`):** منوی هدر و حالت نمایش زیرمنوها در هدر (`inherit` / `dropdown` / `list`).
   - **منوی کشویی موبایل (`slots.drawer` + `drawerDisplayMode`):** منوی موبایل و حالت نمایش آکاردئونی (`dropdown`) یا لیست باز درختی (`list`).
   - **ستون‌های فوتر (`slots.footer`):** هر منویی که تیک بخورد به‌عنوان یک ستون در فوتر اضافه می‌شود و جلوی هر کدام منوی بازشو برای انتخاب حالت نمایش اختصاصی آن ستون (`inherit` / `dropdown` / `list`) وجود دارد. با `slots.footerMode` مشخص می‌کنید به ستون‌های پیش‌فرض اضافه شود (`append`) یا جایگزین آن‌ها شود (`replace`). همچنین `footerDisplayMode` حالت پیش‌فرض فوتر را مشخص می‌کند.
   - **لینک‌های حقوقی پایین فوتر (`slots.legal`):** انتخاب منو برای نوار حقوقی پایین صفحه.
2. **درون صفحات یا قالب‌های دلخواه با `<NavMenu />`:**
   در بالای کارت منو، کد آماده با انتخاب‌گر `displayMode` برای کپی قرار دارد؛ مثلاً:
   ```astro
   <NavMenu menuId="main-nav" displayMode="list" />
   ```
   پراپ‌های کامل `<NavMenu />` شامل `menuId`، `displayMode` (`dropdown` | `list`)، `orientation` (`horizontal` | `vertical`)، `showTitle` و `class` است.

> در پایان کار حتماً روی **«ذخیره تغییرات در client/config.json»** کلیک کنید.

## ۶. مدیریت کامل تنظیمات و منوها بدون Studio (از طریق JSON و CLI)

تمامی تنظیماتی که از طریق تب ۲ در Studio انجام می‌شوند، هیچ وابستگی به رابط گرافیکی ندارند و می‌توانید مستقیماً در فایل **`client/config.json`** (یا از طریق فایل `spec.json` برای دستور `site:apply`) بنویسید.

### الف) ویرایش مستقیم `client/config.json`
فایل `client/config.json` فقط بخش‌هایی را نگه می‌دارد که می‌خواهید روی `app.config.json` بازنویسی شوند. مثال کامل مدیریت منوهای درختی و جایگاه‌ها (هم‌زمان `dropdown` در هدر و `list` در فوتر برای یک آیدی یکسان):

```json
{
  "ui": {
    "navigation": {
      "menus": [
        {
          "id": "main-nav",
          "title": "Main Navigation",
          "titles": {
            "fa": "منوی اصلی",
            "en": "Main Navigation"
          },
          "displayMode": "dropdown",
          "items": [
            {
              "group": "home",
              "icon": "home",
              "labels": { "fa": "خانه", "en": "Home" }
            },
            {
              "id": "services-branch",
              "icon": "layers",
              "labels": { "fa": "خدمات و منابع", "en": "Services & Resources" },
              "childrenDisplay": "inherit",
              "children": [
                {
                  "group": "features",
                  "icon": "sparkles",
                  "labels": { "fa": "امکانات", "en": "Features" },
                  "children": [
                    {
                      "href": "/features/#rtl",
                      "labels": { "fa": "پشتیبانی RTL", "en": "RTL Support" }
                    }
                  ]
                },
                {
                  "contentType": "projects",
                  "icon": "folder",
                  "labels": { "fa": "پروژه‌ها", "en": "Projects" }
                },
                {
                  "href": "https://example.com",
                  "external": true,
                  "labels": { "fa": "مستندات خارجی", "en": "External Docs" }
                }
              ]
            },
            {
              "group": "contact",
              "icon": "mail",
              "labels": { "fa": "تماس با ما", "en": "Contact" }
            }
          ]
        }
      ],
      "slots": {
        "header": "main-nav",
        "headerDisplayMode": "dropdown",
        "drawer": "main-nav",
        "drawerDisplayMode": "dropdown",
        "footerMode": "replace",
        "footerDisplayMode": "list",
        "footer": [
          { "id": "main-nav", "displayMode": "list" }
        ],
        "legal": "legal-nav"
      }
    }
  }
}
```

#### اولویت اعمال `displayMode` در زمان رندر:
1. مقدار صریح در **جایگاه نمایش** (`slots.headerDisplayMode`، `slots.drawerDisplayMode`، `displayMode` در ورودی آبجکت `slots.footer`، `slots.footerDisplayMode` یا پراپ `displayMode` روی `<NavMenu />`) در صورت غیر از `"inherit"` بودن، بر تمام سطوح آن جایگاه اعمال می‌شود.
2. اگر جایگاه روی `"inherit"` باشد، `childrenDisplay` هر گره بررسی می‌شود (در صورت غیر از `"inherit"`).
3. در نهایت اگر گره هم `"inherit"` بود، از `displayMode` خود منو (`"dropdown"` یا `"list"`) پیروی می‌شود.

### ب) اعمال خودکار از طریق فایل Spec و CLI (`site:apply`)
اگر قصد دارید پیکربندی جدیدی را به‌صورت خودکار و همراه با اعتبارسنجی اسکیما اعمال کنید، می‌توانید فایل `spec.json` بسازید (که ساختار آن از همان `ui.navigation` پشتیبانی می‌کند) و اجرا کنید:

```bash
# پیش‌نمایش تغییرات بدون نوشتن روی دیسک
npm run site:apply -- --spec=spec.json --dry-run

# اعمال تغییرات
npm run site:apply -- --spec=spec.json --skip-assets
```

پس از ویرایش دستی `client/config.json`، برای اطمینان از نبود خطای اسکیما یا تایپ‌اسکریپت اجرا کنید:
```bash
npm run check:quick
```

## ۷. تب ۳: CMS و اسکیمای محتوا

این تب سه کارکرد کلیدی دارد:

1. **مدیریت انواع محتوا و اسکیمای کالکشن‌ها (`content.types`):**
   - مشاهده وضعیت همهٔ کالکشن‌ها (`pages`, `blog`, `projects` و کالکشن‌های سفارشی)، مسیر پایه (`base`)، فعال/غیرفعال بودن و تعداد فیلدها.
   - ساخت کالکشن جدید بدون کدنویسی (**`+ ایجاد نوع محتوای جدید`**) یا ویرایش اسکیمای کالکشن‌های موجود (تنظیم فیلدهای سفارشی، فیلترهای `<CollectionBrowser />`، RSS، صفحه‌بندی و ناوبری).
   - فعال یا غیرفعال کردن کالکشن‌ها (`content:enable` / `content:disable`) یا حذف کالکشن‌های Schema-Driven.
2. **همگام‌سازی Pages CMS (`.pages.yml`):**
   - نمایش وضعیت همگام‌سازی `.pages.yml` و پوشه‌های محتوا، مشاهدهٔ متن کامل `.pages.yml` و اجرای تک‌کلیکی `content:sync`.
3. **لایه سوم تنظیمات کارفرما (`client/cms.json`):**
   - فیلدهایی که کارفرما می‌تواند در Pages CMS تغییر دهد (ایمیل تماس، تلفن، واتساپ، تلگرام، آدرس، ساعت کاری، شبکه‌های اجتماعی، وضعیت/متن بنر اطلاع‌رسانی، ویجت تماس سریع و ریدایرکت‌های CMS). ذخیرهٔ این بخش فقط در `client/cms.json` انجام می‌شود و `client/config.json` را دست‌کاری نمی‌کند.

## ۸. تب ۴: صفحات و محتوا

مدیریت کامل فایل‌های MDX در تمام کالکشن‌ها (`pages`, `blog`, `projects` و کالکشن‌های سفارشی):

- **ساخت آیتم جدید:** تعیین کلید گروه (`Group Key` به‌صورت اسلاگ انگلیسی)، عنوان، اسلاگ دلخواه، زبان مبدأ، پریست صفحه (`Standard` یا `Landing`) یا دسته‌بندی/تگ وبلاگ و گزینهٔ انتشار فوری (`--publish`).
- **جدول وضعیت چندزبانه:** برای هر گروه مشخص می‌کند که نسخهٔ هر زبان در چه وضعیتی است (`published`، `draft` یا `missing`)، چند کلمه دارد و آیا دارای `TODO` است یا نه.
- **ویرایش کامل فایل MDX (`ویرایش` / `+ ایجاد`):** باز شدن پنجرهٔ ویرایشگر با تمام فیلدهای Frontmatter (عنوان، اسلاگ، توضیحات، `draft`، **`noindex`** برای خروج از ایندکس ربات‌ها/نقشهٔ سایت/جستجو، انتخاب تصویر از مدیر رسانه `🖼`، فیلدهای اختصاصی کالکشن)، **مبدل زندهٔ دوطرفهٔ تاریخ شمسی ↔ میلادی** کنار فیلدهای `publishedAt` / `updatedAt` و فیلدهای `date` سفارشی (تایپ مستقیم با ارقام فارسی یا انگلیسی مانند `1405/09/06` بدون تغییر فرمت استاندارد `YYYY-MM-DD` فایل MDX)، به‌علاوهٔ **«مقایسه با زبان مرجع»** (نمایش هم‌زمان نسخهٔ زبان مرجع هنگام ترجمه) و **«پیش‌نمایش متن»** (رندر زندهٔ Markdown کنار ادیتور).
- **ترکیب‌بندی سکشن‌های صفحه (`سکشن‌ها` در کالکشن `pages`):** افزودن، جابه‌جایی، حذف و ویرایش سریع پراپ‌های هر سکشن (مانند `LandingHeroSplit`, `FeatureCardGrid`, `FaqAccordion`, `CtaBanner` و...) همراه با انتخاب تصویر، CTA و ویرایش JSON خام `props` برای هر صفحه.
- **حذف امن:** امکان حذف یک زبان خاص از یک گروه یا حذف کل گروه با تأیید دو مرحله‌ای.

## ۹. تب ۵: زبان‌ها و ماتریس ترجمه

این تب بخش چندزبانه‌سازی (`client/locales.json` و `client/messages/*.json` + کامپایل Paraglide) را مدیریت می‌کند:

1. **مدیریت زبان‌های فعال (`client/locales.json`):**
   - ویرایش متادیتای هر زبان (نام، جهت `rtl/ltr`، `htmlLang` و فونت).
   - تغییر زبان پیش‌فرض (`i18n:set-default`) یا تبدیل سایت به حالت تک‌زبانه (`i18n:solo`).
   - حذف زبان (با گزینهٔ آرشیو یا حذف دائم فایل‌های محتوا).
2. **افزودن زبان جدید (`i18n:add-lang`):**
   - ثبت کد زبان (مثل `ar`، `de`، `fr`)، جهت، فونت و کلون اختیاری محتوای صفحات از یک زبان موجود (`--with-content`).
3. **همگام‌سازی و افزودن کلید دیکشنری:**
   - اجرای `i18n:sync-keys` (به‌همراه پیش‌نمایش Dry-Run) برای یافتن و پر کردن کلیدهای جاافتاده با `[TODO: <locale>]`.
   - اجرای `messages:compile` برای بازتولید خروجی Paraglide JS.
   - افزودن کلید اختصاصی جدید (`i18n:add`) به دیکشنری کلاینت برای همهٔ زبان‌ها.
4. **ماتریس تعاملی ویرایش ترجمه‌ها:**
   - جدول کنارهم کلیدها در تمام زبان‌ها با جستجو، فیلتر بر اساس دسته‌بندی یا وضعیت (`Has [TODO:]`, `Client Overridden`, `Empty / Missing`)، صفحه‌بندی، بازگردانی به مقدار Core (`↺ core`) و ذخیرهٔ دسته‌ای + کامپایل خودکار Paraglide.

## ۱۰. تب ۶: CLI، ممیزی و بیلد

اجرای تمام ابزارهای خط فرمان پروژه با یک کلیک و مشاهدهٔ خروجی در کنسول پایین صفحه:

- **تست، تایپ‌چک و ممیزی:** `check:quick`، `lint` (`astro check + tsc`)، `audit:i18n`، `upstream:check`، `doctor`، `doctor --handoff` و `knip`.
- **بیلد استاتیک و بررسی خروجی:** `npm run build` (بیلد SSG + ایندکس جستجوی Pagefind)، `smoke` (تست سلامت `dist/`)، `link:check` (خزش لینک‌ها و ریدایرکت‌ها)، `content:status` و **`preflight (Full Gate)`**.
- **تولید فایل‌ها و همگام‌سازی:** `content:sync`، `messages:compile`، `blocks:catalog` و `assets:generate` (تولید آیکون‌ها و تصاویر OG برنددار).
- **محتوای نمونه و ریست:** `starter:seed` (تزریق محتوای دمو)، `starter:seed --clean` (پاک‌سازی محتوای دمو پیش از تحویل به مشتری) و `site:reset` (بازنشانی تنظیمات کلاینت).
- **پکیج انتقال پروژه مشتری (Client Bundle):** خروجی JSON یک‌جا از تمام لایهٔ `client/` (`locales.json`, `config.json`, `cms.json`, `messages/*.json`) و ایمپورت معتبرسازی‌شده در پروژه‌های مشابه.

## ۱۱. نکات امنیتی و استقرار

- **فقط محیط توسعه:** Studio و تمام endpointهای `/__studio/api/*` صرفاً در سرور توسعه (`astro dev` یا `npm run studio`) فعال هستند و در خروجی نهایی بیلد استاتیک (`npm run build` / `dist/`) هیچ کد، مسیر یا پنلی از Studio وجود **ندارد**.
- **تفکیک سه لایه:** هر تغییری که در Studio یا به‌صورت دستی انجام می‌دهید، فایل‌های هسته (`src/` و `app.config.json`) را دست‌نخورده نگه می‌دارد تا به‌روزرسانی‌های بعدی استارتر بدون تداخل ادغام شوند.
- **پیش از تحویل نهایی پروژه به مشتری:** اجرای دکمه‌های **`doctor --handoff`**، **`audit:i18n`**، **`npm run build`**، **`smoke`** و **`link:check`** (یا دستور `npm run preflight`) توصیه می‌شود.
